O padrão recomendado é gravar cada leitura numa tabela de staging e aplicar no destino
com `MERGE`, mantendo a versão mais recente de cada registro e removendo os excluídos.

## Fluxo

<Steps>
  <Step title="Staging">
    Grave as páginas lidas em tabelas de staging, por exemplo `stg_contacts` e
    `stg_deletions`, sem tratamento.
  </Step>
  <Step title="Merge">
    Aplique no destino a versão mais recente de cada registro, pela chave primária.
  </Step>
  <Step title="Exclusões">
    Remova do destino os registros listados em `/v1/deletions` e, para cada contato
    excluído, os registros dependentes.
  </Step>
  <Step title="Marca d'água">
    Só depois do merge, guarde o `sync_watermark` da última página.
  </Step>
</Steps>

## Merge

O exemplo mostra a tabela de contatos com algumas colunas. Repita o padrão para as demais
colunas e tabelas.

<CodeGroup>

```sql Snowflake
MERGE INTO contacts AS d
USING (
  SELECT * FROM stg_contacts
  QUALIFY ROW_NUMBER() OVER (PARTITION BY id ORDER BY updated_at DESC) = 1
) AS s
ON d.id = s.id
WHEN MATCHED AND s.updated_at >= d.updated_at THEN UPDATE SET
  name = s.name,
  email = s.email,
  phone = s.phone,
  current_stage_id = s.current_stage_id,
  updated_at = s.updated_at
WHEN NOT MATCHED THEN INSERT (id, name, email, phone, current_stage_id, updated_at)
  VALUES (s.id, s.name, s.email, s.phone, s.current_stage_id, s.updated_at);
```

```sql Databricks
-- Com esquemas iguais entre staging e destino, UPDATE SET * e INSERT * copiam todas as colunas.
MERGE INTO contacts AS d
USING (
  SELECT * FROM stg_contacts
  QUALIFY ROW_NUMBER() OVER (PARTITION BY id ORDER BY updated_at DESC) = 1
) AS s
ON d.id = s.id
WHEN MATCHED AND s.updated_at >= d.updated_at THEN UPDATE SET *
WHEN NOT MATCHED THEN INSERT *;
```

```sql BigQuery
MERGE dataset.contacts AS d
USING (
  SELECT * FROM dataset.stg_contacts
  WHERE TRUE
  QUALIFY ROW_NUMBER() OVER (PARTITION BY id ORDER BY updated_at DESC) = 1
) AS s
ON d.id = s.id
WHEN MATCHED AND s.updated_at >= d.updated_at THEN UPDATE SET
  name = s.name,
  email = s.email,
  phone = s.phone,
  current_stage_id = s.current_stage_id,
  updated_at = s.updated_at
WHEN NOT MATCHED THEN INSERT (id, name, email, phone, current_stage_id, updated_at)
  VALUES (s.id, s.name, s.email, s.phone, s.current_stage_id, s.updated_at);
```

</CodeGroup>

Em `contact_fields`, que não tem `id`, use `ON d.contact_id = s.contact_id AND
d.field_key = s.field_key` e particione por essas duas colunas.

## Exclusões

A exclusão de um contato remove também as conversas, os valores de campo e as mudanças
de etapa dele. O mesmo SQL funciona nos três bancos:

```sql
DELETE FROM conversations
WHERE id IN (SELECT object_id FROM stg_deletions WHERE object_type = 'conversation')
   OR contact_id IN (SELECT object_id FROM stg_deletions WHERE object_type = 'contact');

DELETE FROM contact_fields
WHERE contact_id IN (SELECT object_id FROM stg_deletions WHERE object_type = 'contact');

DELETE FROM stage_events
WHERE contact_id IN (SELECT object_id FROM stg_deletions WHERE object_type = 'contact');

DELETE FROM contacts
WHERE id IN (SELECT object_id FROM stg_deletions WHERE object_type = 'contact');
```

No BigQuery, qualifique as tabelas com o dataset (`dataset.contacts`).
